# 前后端分离改造计划（简化版）

## Context（背景）

当前项目是 Flask SSR + API 混合架构：server.py（6021）用 Jinja2 渲染页面 + 处理表单 POST，api_server.py（8080）提供 JSON 接口。

用户要求改成纯前后端分离，约束：
- **不引入任何新库**（不要 PyJWT，认证继续用 Flask 原生 Cookie + Session）
- **纯 HTML + CSS + JS**（去掉所有 Jinja2 语法）
- **common.py 只管数据库和端口配置**（不塞认证逻辑进去，保持现状不动）

## 总体方案

**认证完全不变**：继续用 Flask session + Cookie，`login_required`/`admin_required`/`sign_in` 全部保留原样。前端 fetch 继续带 `credentials:'include'`，CORS 继续 `supports_credentials=True`。不引入 JWT，不引入任何新依赖。

**改造重点只有两件事**：
1. **前端**：18 个 HTML 模板去掉所有 Jinja2 语法（`{{ }}`、`{% %}`），改成纯静态 HTML + JS fetch 加载数据 + JS fetch 提交表单
2. **后端**：server.py 从 SSR 改成纯静态文件托管；api_server.py 新增聚合接口把原 SSR 注入的数据以 JSON 返回

**common.py 完全不动**——数据库连接、端口配置、`login_required`/`admin_required`/`sign_in`/`verify_login`/`db_cursor`/`init_db` 等全部保持原样。

## 一、后端改造

### server.py（6021）→ 纯静态文件托管

**删除**：所有 SSR 视图函数（login/register/forgot_password/orders/users/settings/production/hmi/line/virtual/alarms/recipes/index/update_status/delete_order/logout/change_password）、`_backend_request`、`_backend_*` 系列、`inject_auth`（context_processor）、`manage_user_action`、`captcha_image`、`_gen_captcha_code`

**保留**：
- `app = Flask(...)` 实例（static_folder 指向 frontend/static）
- `app.secret_key`（session 仍用于认证）
- `init_db()` 调用
- `SEND_FILE_MAX_AGE_DEFAULT = 0`

**新增**：SPA 式静态路由
```python
from flask import Flask, send_from_directory

app = Flask("wodeserver",
    static_folder=os.path.join(FRONTEND_DIR, "static"),
    template_folder=None)  # 不再需要模板目录

PAGES = ["", "login", "register", "forgot_password", "orders", "production",
         "hmi", "station_st01", "line", "virtual", "settings", "users",
         "recipes", "alarms", "forbidden"]

@app.route("/")
@app.route("/<page>")
def serve_page(page=""):
    name = page or "index"
    return send_from_directory(os.path.join(FRONTEND_DIR, "Templates"), f"{name}.html")
```

**验证码**：保留 `/captcha` 路由在 server.py（它只生成图片，不依赖 Jinja2，session 存 captcha_answer 仍然有效——因为 6021 和 8080 共享 secret_key + .epoch，session 跨服务可读）。

### api_server.py（8080）→ 新增聚合接口

把 server.py 原来 `render_template(... inject=...)` 注入的数据，改成 JSON 接口返回。现有接口（`/api/stats`、`/api/line`、`/api/plc_status` 等）全部保留不动。

**新增接口清单**：

| 新接口 | 方法 | 来源 SSR 路由 | 返回内容 |
|---|---|---|---|
| `/api/auth/login` | POST | server.py `/login` POST | 校验验证码+账号密码，成功返 `{ok:true}`，失败返 `{ok:false, error}` |
| `/api/auth/register` | POST | server.py `/register` POST | 注册，返 `{ok:true/false, message}` |
| `/api/auth/forgot_password` | POST | server.py `/forgot_password` POST | 重置密码，返 JSON |
| `/api/auth/logout` | POST | server.py `/logout` | 清 session，返 `{ok:true}` |
| `/api/auth/me` | GET | context_processor inject_auth | 返当前用户信息 `{username, display_name, role, is_admin}` |
| `/api/orders` | GET | server.py `/orders` GET | 返 `{orders, stats, products, default_order_no, today, is_admin}` |
| `/api/orders` | POST | server.py `/orders` POST | 新建工单，返 `{ok:true}` 或 `{ok:false, error}` |
| `/api/orders/<id>` | DELETE | server.py `/delete_order/<id>` | 删工单 |
| `/api/orders/<id>/status` | POST | server.py `/update_status/<id>/<status>` | 改工单状态 |
| `/api/users` | GET | server.py `/users` GET | 返用户列表 + root_admin |
| `/api/users/action` | POST | server.py `/users` POST | 处理 disable/enable/reset/role/delete |
| `/api/settings` | GET | server.py `/settings` GET | 返 PLC 配置 + 产品 + 工位 |
| `/api/settings` | POST | server.py `/settings` POST | 改 PLC 配置 |
| `/api/change_password` | POST | server.py `/change_password` POST | 改密码（已是 JSON，搬过来） |
| `/api/production/stats` | GET | server.py `/production` GET | 返 records/trend/station_stats |
| `/api/recipes` | GET | server.py `/recipes` GET | 返 products/stations |
| `/api/alarms` | GET | server.py `/alarms` GET | 返 line + logs |
| `/api/line/page` | GET | server.py `/line` GET | 返 line + records + logs |
| `/api/virtual/page` | GET | server.py `/virtual` GET | 返虚拟产线快照 |
| `/api/hmi/page` | GET | server.py `/hmi` GET | 返 plc_ip/port + line |
| `/api/station_st01/page` | GET | server.py `/station_st01` GET | 返 plc_ip/port |

**设计原则**：页面初始数据用聚合接口一次返齐，前端一次 fetch 拉取渲染整页。

**`manage_user_action` 迁移**：从 server.py 搬到 api_server.py，所有 `session.get("username")` 保持不变（session 在 8080 仍然有效，因为共享 secret_key + .epoch）。

**原 `/api/login` 处理**：删除（被 `/api/auth/login` 替代）。

### common.py → 不动

完全保持现状。`login_required`/`admin_required`/`sign_in`/`verify_login`/`session_signature`/`db_cursor`/`init_db`/`get_user`/`add_log`/`order_stats` 等全部不改。不引入任何新函数、新 import。

## 二、前端改造

### app.js → fetch 包装器（微调）

当前 app.js 的 fetch 包装器已经带 `credentials:'include'` 和 401 跳登录，**基本不用改**。只需把 `window.API_BASE` 从 Jinja2 注入改成 JS 硬编码：

```javascript
// 原来由 base.html 注入：<script>window.API_BASE = '{{ api_base }}';</script>
// 改成 app.js 顶部硬编码：
window.API_BASE = window.API_BASE || ('http://' + location.hostname + ':8080');
```

其余（`credentials:'include'`、401 跳 `/login`、`postJSON`/`getJSON` 封装）全部保留。

### base.html → 纯静态骨架

去掉所有 Jinja2 语法。18 个页面各自是独立 .html，复制 sidebar/topbar/modal 骨架（静态结构），由 base.js 动态填充用户信息和导航高亮。

**关键改动**：
- `{% block title/extra_css/content/extra_js %}` → 每个页面直接写对应内容
- `{% if scope == 'admin' %}` → 管理员导航项初始 `hidden` + `class="admin-only"`，base.js 根据角色显示
- `{{ username }}`/`{{ role_label }}`/`{{ is_admin }}` → 空标签带 id，base.js 填充
- `{{ url_for('static', ...) }}` → 直接写 `/static/css/xxx.css`
- `window.API_BASE = '{{ api_base }}'` → 删除，由 app.js 硬编码

### base.js → 重写

```javascript
// 页面加载时拉取用户信息，渲染顶栏 + 导航
fetch('/api/auth/me', {credentials:'include'})
  .then(r => r.json()).then(res => {
    if (!res.ok) { location.href = '/login'; return; }
    const user = res.data;
    // 填充用户名、角色
    document.querySelectorAll('#username-display').forEach(el => el.textContent = user.display_name);
    document.querySelectorAll('#role-chip').forEach(el => {
      el.textContent = user.role === 'admin' ? '管理员' : '操作员';
      el.className = 'role-chip ' + user.role;
    });
    // 管理员导航显示
    if (user.role === 'admin') {
      document.querySelectorAll('.admin-only').forEach(el => el.hidden = false);
    }
    // 当前页高亮
    const page = document.body.dataset.page;
    document.querySelectorAll(`.side-link[data-active="${page}"]`).forEach(el => el.classList.add('active'));
  });
// 保留 /api/stats 轮询顶栏状态药丸（已有逻辑不动）
```

### 各页面初始数据：Jinja2 注入 → fetch 加载

- HTML 里只留**空容器带 id**（`<span id="currentOrder">--</span>`）
- JS 启动时调聚合接口或现有接口填充
- 能复用现有接口就复用（如 home.js 用 `/api/line` + `/api/stats` + `/api/logs`），缺什么补什么

### 表单：POST 整页提交 → fetch POST

```javascript
document.getElementById('loginForm').addEventListener('submit', async (e) => {
    e.preventDefault();
    const res = await fetch('/api/auth/login', {
        method: 'POST',
        headers: {'Content-Type': 'application/json'},
        credentials: 'include',
        body: JSON.stringify({
            username: e.target.username.value,
            password: e.target.password.value,
            captcha: e.target.captcha.value
        })
    }).then(r => r.json());
    if (res.ok) { window.location.href = '/'; }
    else { showError(res.error); refreshCaptcha(); }
});
```

### 错误提示：`{% if error %}` → JS DOM 操作

```html
<div class="error-msg" id="errorBox" hidden></div>
```
```javascript
function showError(msg) {
    const box = document.getElementById('errorBox');
    box.textContent = msg;
    box.hidden = false;
}
```

### 页面跳转：redirect → window.location.href

后端返 `{ok:true}` 或 `{ok:false, error:...}`，前端拿 ok 后自己跳。

## 四、关键风险

- **R1 后台线程**：`poll_plc_status`/`line_simulator` 等后台线程没有 request context，不能用 `session.get`。这些地方原来也是 None，保持不变即可
- **R2 验证码跨服务**：captcha answer 存 session（6021 签发），登录在 8080 校验。当前架构已通过共享 secret_key + .epoch 解决，**不用改**
- **R3 进度控件 JS 渲染**：必须与原 `_widgets.html` 宏逻辑逐字段对齐（pct 计算、disabled 边界、aria 属性）
- **R4 users.html 权限分支**：`manage_user_action` 搬迁后保持 `session.get("username")` 不变（session 在 8080 有效）
- **R5 base.html 骨架复制**：18 个页面复制 sidebar/topbar 骨架，未来改导航需要 18 处替换（用 IDE 全局替换可接受）

## 五、验证方法

- **阶段 1**：curl/Postman 测每个新接口，session cookie 鉴权通过
- **阶段 3**：浏览器端到端测注册→登录→退出→找回密码
- **阶段 4**：每改一个页面对照原行为跑一遍（建工单、改进度、改状态、删工单、改 PLC 配置、改密码、停用账号、下发产线、模拟故障）
- **阶段 5**：双服务重启 + 全量回归
