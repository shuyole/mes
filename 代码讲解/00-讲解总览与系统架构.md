# 00 · MES 项目代码讲解总览与系统架构

> 本文件是整套讲解的入口。项目是一个「智能无线充组装产线 MES（制造执行系统）」教学项目，
> 后端用 Python + Flask，前端是传统的 HTML（Jinja2 模板）+ CSS + 原生 JavaScript 三件套，
> 没有使用 Vue/React 等框架。

## 二、系统总体架构：两个 Flask 进程 + 一个虚拟 PLC 进程

本项目刻意把「页面」和「接口」拆成两个独立的 Python 进程：

| 进程 | 文件 | 端口 | 职责 |
|---|---|---|---|
| 前端页面服务 | `backend/server.py` | **6021** | 渲染 HTML 页面、处理传统表单 POST、生成验证码图片、转发后端请求 |
| 后端接口服务 | `backend/api_server.py` | **8080** | 全部 `/api/*` JSON 接口、Modbus TCP 读写 PLC、产线仿真后台线程、PLC 轮询线程 |
| 虚拟 PLC（可选） | `backend/virtual_plc.py` | **502** | 用 pymodbus 模拟一台 Modbus TCP 从站，免硬件联调 |

两个 Flask 服务**共用同一份 `common.py`、同一个 `config/config.json`、同一个数据库、同一个 secret_key
和同一个 `data/.epoch` 会话代次文件**，所以浏览器在 6021 登录拿到的 Cookie，直接请求 8080 也有效。

### 请求流转的三种路径

1. **打开页面（服务端渲染）**
   浏览器 → `http://主机:6021/orders` → server.py 查数据库 → 用 Jinja2 把 orders.html 渲染成 HTML 返回。

2. **页面上的实时刷新（前后端分离式 JSON）**
   页面加载后，JS 用 `fetch('/api/...')` 要数据 → app.js 的 fetch 包装器自动加上 8080 前缀
   → `http://主机:8080/api/plc_status` → api_server.py 返回 JSON → JS 更新 DOM（页面不刷新）。

3. **6021 替浏览器调 8080（服务端内部转发）**
   个别操作（如设置页保存 PLC 地址、老的状态流转链接）由 server.py 用 `urllib.request`
   调本机 8080，并把浏览器 Cookie 原样转发，权限校验与浏览器直连完全一致。

### 后台常驻线程（只在 api_server.py 中启动）

- `line_simulator`：产线仿真主循环，按倍速每个「节拍」推进 7 个工位的加工进度；
  真实产线只在 PLC 在线时推进，虚拟产线始终可跑；过程中写数据库、写日志、写 PLC 寄存器。
- `poll_plc_status`：每 2 秒读一次 PLC 的 0~7 号保持寄存器，刷新连接状态缓存 `PLC_STATE`，
  并监视 HR0 的边沿变化（0停/1运行/3故障），实现「PLC/HMI → 虚拟产线」的反向控制。

## 三、业务背景：7 工位无线充组装产线

`common.py` 中的 `STATION_DEFS` 是全项目的工艺主数据，前端页面和后端仿真都围绕它：

| 工位 | 名称 | 节拍 | PLC 寄存器 | 角色 |
|---|---|---|---|---|
| ST01 | 自动上料 | 3s | HR10 | 治具定位、真空吸盘取料 |
| ST02 | 主板安装 | 4s | HR11 | CCD 视觉对位、PCBA 装配 |
| ST03 | 后盖安装 | 4s | HR12 | 线圈预置、后盖保压 |
| ST04 | 螺丝锁附 | 4s | HR13 | 伺服电批扭矩监控 |
| ST05 | 激光打标 | 4s | HR14 | SN 码与二维码镭雕 |
| ST06 | 成品检测 | 5s | HR15 | Qi2 协议、FOD、温升 |
| ST07 | 自动下料 | 3s | HR16 | 机械臂分拣良品/不良品 |

每个工位还带有：传感器信号（DI 点表）、工艺参数与公差标准、质量判定标准，
这些数据通过「工位诊断抽屉」和 ST01 专用页面展示。

### PLC 保持寄存器（HR）约定

| 寄存器 | 含义 | 取值 |
|---|---|---|
| HR0 | 产线状态字 | 0 停止 / 1 运行 / 2 完成 / 3 故障 |
| HR1 | 当前工位 | 1~7 对应 ST01~ST07 |
| HR2 | 当前产量 | 整数 |
| HR4 / HR5 | 合格数 / 不良数 | 整数 |
| HR6 | 机械臂状态 | 0 待机 / 1 运行 / 2 故障 |
| HR10~HR17 | 预留给 ST01 上料模块 | 虚拟从站初值全 0 |

### 数据库 6 张表（init_db 自动建表，MySQL 优先、SQLite 兜底）

- `users` 用户（账号、werkzeug 密码哈希、角色 admin/member、状态、学号）
- `production_orders` 工单（单号、产品、数量、优先级、完成数、不良数、进度、状态、当前工位…）
- `work_records` 过站记录（每完成一个工位写一条：合格/不良）
- `production_logs` 生产日志（INFO/WARN/ALARM，分 sys 系统类与 line 产线类）
- `products` 产品主数据（由代码中的 PRODUCTS upsert 同步）
- `line_stations` 工位主数据（由 STATION_DEFS upsert 同步）

此外 `data/sync/*.json` 是这 6 张表的 JSON 快照，每次写库后自动导出；
切换数据库时会自动把快照 REPLACE 回填进新库，保证换库不丢教学数据。

## 四、前端「HTML / CSS / JS 三类」对应关系（速查）

前端严格按三类分目录：`Templates/` 放 HTML、`static/css/` 放 CSS、`static/js/` 放 JS；
约定**每个实际渲染的 HTML 页面在 css/、js/ 下各有一个同名文件**（个别页共用 progress.js
等功能脚本，无交互的页面 JS 可只放轻量增强）。

### 4.1 HTML 与页面路由

所有业务页都 `{% extends "base.html" %}` 继承同一个母版；登录/注册/找回密码是独立整页。

| URL（6021） | server.py 视图 | HTML 模板 | 权限 |

| `/line` | line_page | line.html（mode=real） | 登录 |
| `/virtual` | virtual_page | line.html（mode=virtual） | 登录 |
| `/orders` | orders_page | orders.html | 登录 |
| `/production` | production_page | production.html | 登录 |
| `/recipes` | recipes_page | recipes.html | 登录 |
| `/alarms` | alarms_page | alarms.html | 登录 |

### 4.2 每个页面加载的 CSS 与 JS

| HTML 页面 | CSS | 专属 JS |
|---|---|---|
| 母版 base.html（被所有业务页继承） | app.css + console.css + base.css | form.js + app.js + base.js（所有业务页全局生效） |
| home.html | + home.css | home.js |
| line.html（/line 与 /virtual 共用） | + line.css | line.js（用 window.LINE_MODE 区分真实/虚拟） |
| orders.html | + orders.css | orders.js + progress.js |
| production.html | + production.css | production.js（Chart.js CDN）+ progress.js |
| hmi.html | + hmi.css | hmi.js |
| station_st01.html | + station_st01.css | station_st01.js（轮询 /api/station_st01） |
| recipes | + recipes.css | recipes.js（滚动入场动画） |
| alarms | + alarms.css | alarms.js（data-action 事件委托调 postJSON） |
| settings / users | + settings.css / users.css | settings.js / users.js（表单校验与防重复提交） |
| forbidden | + forbidden.css | forbidden.js（5 秒自动跳转倒计时） |
| login / register / forgot_password | 同名 css（独立页，无 base.css） | 同名 js（粒子动效）+ form.js |
| change_password | change_password.css | change_password.js（校验与提交锁）+ form.js |

加载顺序要点：母版页 `app.css`（基础组件）→ `console.css`（HUD 皮肤，后加载覆盖）
→ `base.css`（母版专属）→ 各页 `extra_css` 块里的同名 CSS（最后加载优先级最高）。
JS 顺序：form.js → 注入 `window.API_BASE` → app.js → base.js → 各页 `extra_js` 块里的同名脚本。

### 4.3 三类文件各自的角色

- **HTML（Templates/*.html）**：负责「页面上有什么」。Jinja2 负责继承（extends）、
  循环（{% for %} 渲柒工单/工位表格）、权限分支（{% if is_admin %}）和数据注入
  （{{ line|tojson }} 把后端数据塞进隐藏 script 供 JS 读取）。
- **CSS（static/css/*.css）**：负责「长什么样」。app.css 是组件库，console.css 是深色
  HUD 皮肤，base.css 是母版骨架专属样式；其余每页一份同名 CSS，只放该页独有的布局类。
- **JS（static/js/*.js）**：负责「怎么动」。app.js 提供全局能力（fetch 跨端口代理、音效、
  Toast、弹窗、诊断抽屉、倍速、全屏、快捷键），form.js 做表单校验，base.js 管顶栏时钟与
  状态轮询；其余每页一份同名 JS，按页面分工，用定时器轮询 8080 接口刷新界面。

## 五、鉴权与权限模型

- 登录方式有两种：网页表单 POST `/login`（带图形验证码 `/captcha`），或 JSON `POST 8080/api/login`。
- 密码用 werkzeug 的 `generate_password_hash / check_password_hash`，数据库不存明文。
- 登录成功后 session 写入用户信息和一个**会话指纹** `sign = sha256(data/.epoch + 用户名 + 密码哈希)`；
  每次请求 `login_required` 重新比对，改密码或删除 `.epoch` 会让旧会话立即失效。
- 两级角色：`admin`（管理员）与 `member`（普通成员）。
  - `@login_required`：拦截未登录，API 返回 401 JSON，页面跳转登录页。
  - `@admin_required`：再拦截非管理员，API/POST 返回 403 JSON，页面渲染 forbidden.html。
  - 模板里用 `{% if is_admin %}` / `scope == 'admin'` 隐藏管理员入口和按钮（前端仅隐藏，后端仍二次校验）。
- 初始内置管理员：`admin / ADMIN`；普通账号可自助注册（角色固定 member），
  可用「账号 + 学号」自助找回密码；admin 账号禁止注册占用、不支持自助找回。
- 任意登录用户可在顶栏进入 `/change_password` 自助修改**本人**密码（校验旧密码、
  新密码 ≥6 位且两次一致、新旧不同）；改密成功后服务端立即重签会话，不会被踢下线。

## 六、启动方式

分别启动两个服务（顺序不限，server.py 调不到 8080 时页面仍能用离线兜底数据打开）：

```bash
python backend/api_server.py   # 8080：先初始化数据库，再起 PLC 轮询 + 仿真线程
python backend/server.py       # 6021：打开浏览器访问 http://127.0.0.1:6021
```

PLC 地址在 `config/config.json` 里配置：填 `127.0.0.1` 时 api_server 会自动拉起
`virtual_plc.py` 虚拟从站；填真实 PLC 的 IP 时会自动停止虚拟从站。
