# 01-系统架构与三服务设计

## 1. 为什么设计成“三服务”？

很多初学者在刚学 Web 开发时，习惯于写一个单一的 Python 文件（例如把路由、页面渲染、数据库连接全写在 `app.py` 里面）。这种方式在简单写几行代码时很方便，但是一旦项目稍微复杂一点，就会遇到以下致命问题：

1. **前后端代码混在一起**：HTML 里面嵌入了 Python 模板语法（如 `{{ username }}`），前端写样式的人改一下 HTML，就会把后端的模板标签弄坏。
2. **端口混乱**：不知道浏览器访问的到底是前端静态页面还是后端接口。
3. **数据库连接分散**：如果有多处代码都在连数据库，容易出现连接泄露、并发锁死等难以排查的 Bug。

为了让初学者掌握现代 Web 开发的标准理念，本项目采用了清晰的**三服务分层架构**：

```text
               ┌───────────────────────┐
               │    浏览器 (用户端)     │
               └───────────┬───────────┘
                           │
             ┌─────────────┴─────────────┐
             │                           │
  [1] 请求静态页面 (6031)       [2] 异步数据交互 (8090)
             ▼                           ▼
┌─────────────────────────┐ ┌─────────────────────────┐
│  前端静态服务 (Port:6031)│ │  后端接口服务 (Port:8090)│
│  (backend/static_server)│ │   (backend/api_server)  │
│  • 专职托管 HTML/CSS/JS  │ │  • 专职处理业务逻辑     │
│  • 不接触任何数据库      │ │  • 只返回纯 JSON 数据   │
└─────────────────────────┘ └────────────┬────────────┘
                                         │
                                [3] 转发 SQL 请求 (6070)
                                         ▼
                            ┌─────────────────────────┐
                            │  数据库代理服务 (Port:6070│
                            │   (backend/db_server)   │
                            │  • 全系统唯一连接数据库  │
                            │  • 执行原生 SQL 并回传结果│
                            └────────────┬────────────┘
                                         │
                               ┌─────────┴─────────┐
                               ▼                   ▼
                     ┌──────────────────┐ ┌──────────────────┐
                     │ backend/db_sqlite│ │ backend/db_mysql │
                     │ (SQLite 独立文件) │ │ (MySQL 独立文件) │
                     └──────────────────┘ └──────────────────┘
```

## 2. 各个服务的职责划分

### ① 前端静态服务（6031 端口）
- **对应代码**：`backend/static_server.py`
- **主要工作**：它就像一个极简的 Nginx 或 Apache 静态服务器，当你在浏览器输入 `http://127.0.0.1:6031/login` 时，它负责把 `frontend/Templates/login.html` 原封不动地读出来发给浏览器。
- **关键特点**：它里面**完全没有数据库代码**，也**不包含任何业务接口**。

### ② 后端接口服务（8090 端口）
- **对应代码**：`backend/api_server.py` 与 `backend/routes/auth.py`
- **主要工作**：它是纯粹的 API 接口服务。前端通过 JavaScript 发起 `fetch('http://127.0.0.1:8090/api/login')` 请求时，由它来解析参数、验证验证码、判断密码是否正确。
- **关键特点**：它只和 JSON 打交道，接收 JSON，返回 JSON，**绝不返回 HTML 页面**。

### ③ 数据库代理服务（6070 端口）
- **对应代码**：`backend/db_server.py`
- **主要工作**：它是数据访问的唯一网关。后端接口服务想要查询或写入数据时，把 SQL 语句和参数打包成 JSON，发送给 6070 服务的 `/query` 或 `/execute` 接口。
- **关键特点**：整个系统中**只有它才真正连数据库**。无论底层是 SQLite 文件还是远程 MySQL 服务器，都由它来隔离差异。

## 3. 一键启动脚本 `start.bat` 工作原理

初学者在本地运行时，不需要手动打开三个黑窗口分别输命令。项目根目录下的 `start.bat` 已经为您写好了一键启动逻辑：

```bat
:: 1. 启动 6070 数据库服务
start "AuthSystem-DBServer[6070]" /min python backend/db_server.py

:: 2. 启动 8090 后端接口服务
start "AuthSystem-APIServer[8090]" /min python backend/api_server.py

:: 3. 启动 6031 前端静态服务
start "AuthSystem-StaticServer[6031]" /min python backend/static_server.py

:: 4. 等待 2 秒确保服务就绪后，自动唤起浏览器
start http://127.0.0.1:6031/login
```

这样一键点击，三个服务即可在后台就绪，并且自动打开浏览器登录页面。
