# 02-后端接口与认证流程

本项目后端的所有业务接口都集中在 `backend/routes/auth.py` 文件中。代码遵循“直白、少抽象、易阅读”的原则，非常适合初学者理解后端处理请求的全过程。

---

## 1. 核心接口清单

| 接口地址 | 请求方式 | 主要功能 | 接收参数 (JSON) | 返回数据格式 |
| :--- | :--- | :--- | :--- | :--- |
| `/api/captcha` | `GET` | 生成并返回图形验证码图片 | 无 | `image/png` 图片二进制流 |
| `/api/login` | `POST` | 用户登录认证 | `username`, `password`, `captcha` | `{ "ok": true, "message": "...", "user": {...} }` |
| `/api/register` | `POST` | 新用户账号注册 | `username`, `real_name`, `student_id`, `password`, `captcha` | `{ "ok": true, "message": "注册成功" }` |
| `/api/forgot_password` | `POST` | 学号身份核验找回密码 | `username`, `student_id`, `new_password`, `captcha` | `{ "ok": true, "message": "密码重置成功" }` |
| `/api/change_password` | `POST` | 个人中心修改密码 | `username`, `old_password`, `new_password` | `{ "ok": true, "message": "密码修改成功" }` |

---

## 2. 核心业务处理流程详解

### 2.1 验证码生成与核验 (`/api/captcha`)
- **生成方式**：使用 Python 著名的图像处理库 `Pillow`，随机选取 4 位大写字母与数字（去掉了易混淆的 0、O、I、1）。
- **绘制效果**：动态添加彩色背景与随机噪点线，防止脚本暴力破解。
- **存储机制**：生成的文本直接保存在服务进程的内存变量 `CURRENT_CAPTCHA` 中。每次前端点击图片时重新生成并覆盖。

### 2.2 用户登录接口 (`/api/login`)
登录流程极其直观，分为三步：
1. **核对验证码**：如果前端输入的验证码与当前生成的验证码不一致，直接返回错误：
   ```json
   { "ok": false, "message": "验证码错误或已失效" }
   ```
2. **查询数据库**：通过 `common.db_query()` 查询数据库中是否存在该用户名，且密码是否一致。
3. **返回用户信息**：如果核对成功，直接将用户的基本资料组织成字典返回：
   ```json
   {
     "ok": true,
     "message": "登录成功",
     "user": {
       "username": "admin",
       "display_name": "管理员",
       "role": "admin",
       "role_label": "管理员"
     }
   }
   ```
> **注意**：整个流程中**完全没有写任何 session**。前端拿到 `user` 对象后，自行存入浏览器的 `localStorage`，做到了完全无状态、高可靠。

### 2.3 注册与学号防伪 (`/api/register`)
在初学者的学生管理系统或企业管理系统中，账号绑定学号/工号是非常经典的设计：
- 前端提交 `username`、`real_name`、`student_id`。
- 后端先检查该用户名或学号是否已经被他人注册。
- 确认无冲突后，执行 `INSERT INTO users (...) VALUES (...)` 写入数据库。

### 2.4 找回密码流程 (`/api/forgot_password`)
- 很多初学者的忘记密码功能难以落地（因为发邮件需要配置 SMTP 邮箱密码，发短信需要花钱买短信 API 服务）。
- 本项目采用最实用的**安全凭证找回方式（学号/工号校验）**：
  只要用户能准确说出自己的“用户名”和“注册时登记的学号”，系统就认定其为账号本人，允许直接更新 `password` 字段为新密码。
