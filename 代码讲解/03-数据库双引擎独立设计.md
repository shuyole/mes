# 03-数据库双引擎(SQLite与MySQL)独立设计

在许多初学者开源项目中，为了“偷懒”同时支持 SQLite 和 MySQL，通常会把两者的代码混在一起，例如写成：
```python
# 常见的糟糕写法（不可取！）：
sql = "SELECT * FROM users WHERE username = %s"
if is_sqlite:
    sql = sql.replace("%s", "?")  # 运行期字符串替换，极其容易出错！
```
这种写法存在严重隐患：一旦 SQL 语句包含百分号（如 `LIKE '%abc%'`），替换就会把正常的字符也替换掉，引发隐晦莫测的 SQL 语法错误。

为了让初学者看到**规范、干净、工业级严谨**的代码，本项目将两者完全拆分为两个独立的文件。

---

## 1. 原生 SQLite 模块 (`backend/db_sqlite.py`)

### 1.1 技术特点
- **免安装**：使用 Python 标准库自带的 `sqlite3` 模块，初学者电脑不需要安装任何 MySQL 或数据库服务端。
- **文件存储**：数据直接保存在本地磁盘 `data/auth.db` 文件中。
- **原生标准占位符**：严格使用 SQLite 规定的原生问号占位符 `?`。

### 1.2 核心实现代码片段
```python
import sqlite3

def get_connection():
    # 连接本地磁盘文件
    conn = sqlite3.connect("data/auth.db")
    conn.row_factory = sqlite3.Row  # 让查询结果可以按字段名取值
    return conn

def execute_query(sql, params=None):
    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute(sql, params or ())
    rows = [dict(row) for row in cursor.fetchall()]
    conn.close()
    return rows
```

## 2. 原生 MySQL 模块 (`backend/db_mysql.py`)

### 2.1 技术特点
- **企业级应用**：使用流行的 `pymysql` 库，方便未来将系统部署到真实服务器。
- **自动建库**：初次连接时会自动执行 `CREATE DATABASE IF NOT EXISTS auth_db`，无需手动在 Navicat 中敲建库命令。
- **原生标准占位符**：严格使用 MySQL 规定的原生占位符 `%s`。

### 2.2 核心实现代码片段
```python
import pymysql

def get_connection():
    # 从配置中读取 host, user, password, port
    return pymysql.connect(
        host=cfg["host"],
        user=cfg["user"],
        password=cfg["password"],
        database=cfg["name"],
        cursorclass=pymysql.cursors.DictCursor
    )

def execute_query(sql, params=None):
    conn = get_connection()
    cursor = conn.cursor()
    cursor.execute(sql, params or ())
    rows = cursor.fetchall()
    conn.close()
    return rows
```

## 3. 数据库代理服务 (`backend/db_server.py`) 如何统一管理？

在 `backend/db_server.py` 中，程序根据 `config.json` 的配置，只进行一次纯粹的导入判断：

```python
# 根据配置直接载入对应的模块文件
if DB_TYPE == "mysql":
    import db_mysql as db
else:
    import db_sqlite as db
```

此后，无论是 SQLite 还是 MySQL，都暴露完全一致的标准函数：
- `db.init_db()`：初始化数据表与默认管理员。
- `db.execute_query(sql, params)`：执行查询并返回列表。
- `db.execute_update(sql, params)`：执行增删改并返回影响行数。

上层的 `api_server` 只需要通过 HTTP 请求 6070 端口，即可完成所有数据库操作，真正做到了**低耦合、高内聚**。
