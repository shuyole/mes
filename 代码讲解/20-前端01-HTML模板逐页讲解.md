# 20 · 前端代码讲解（一）：HTML 模板逐页讲解（Templates/ 共 19 个）

> 目录：`frontend/Templates/`
> 技术：Jinja2 模板（Flask 服务端渲染）。业务页面全部 `{% extends "base.html" %}`，
> 登录/注册/找回密码/修改密码是独立整页。文件名以 `_` 开头的 `_widgets.html` 不是页面，
> 而是供其他模板 import 的 Jinja 宏库。
>
> **模块化约定（2026-09 重构后）**：每个实际渲染的 HTML 页面都在 `static/css/` 与
> `static/js/` 下拥有**同名**的专属文件（如 `orders.html` ↔ `css/orders.css` ↔ `js/orders.js`），
> 页面通过母版的 `extra_css` / `extra_js` 区块引入；模板内不再写大段内联 `<style>`/`<script>`，
> 仅保留两类内联脚本：① 注入配置/数据的一行脚本（`window.API_BASE`、`window.LINE_MODE`、
> `type="application/json"` 的 initialLine / productionData）；② 调用外部 JS 既有全局函数的
> 元素 onclick（如 sendCommand、openStationDrawer）。

---

## 0. Jinja2 语法速览（看本项目模板前先认识这 5 个）

| 语法 | 含义 | 项目中的例子 |
|---|---|---|
| `{{ 变量 }}` | 输出变量 | `{{ username }}`、`{{ order.quantity }}` |
| `{% if %} ... {% endif %}` | 条件分支 | `{% if is_admin %}` 控制管理员按钮 |
| `{% for x in 列表 %} ... {% endfor %}` | 循环 | 遍历 7 个工位、工单列表 |
| `{% extends %}` / `{% block %}` | 继承母版、覆盖区块 | 每页填充 title/content/extra_css/extra_js |
| `{{ 数据|tojson }}` | 把 Python 对象转成 JS 对象 | 把产线快照、图表数据内嵌给 JS |

母版 base.html 定义了 4 个可覆盖区块：`title`、`extra_css`、`content`、`extra_js`。

## 1. base.html —— 全站母版（所有业务页面的骨架）

### 1.1 结构

`<head>` 里固定加载 app.css → console.css → base.css，再留 `{% block extra_css %}` 放页面专属 CSS；
`<body>` 里是 `.app-shell` 三栏布局：

- **aside.sidebar 左侧导航**：品牌区 + 四组导航（生产监控 / 生产执行 / 设备控制 / 系统管理），
  每个 `<a class="side-link">` 用 `{{ 'active' if active_page=='xxx' }}` 高亮当前页；
  ST01、HMI、设置、用户管理四个入口包在 `{% if scope == 'admin' %}` 里，普通成员看不到；
  侧栏底部显示角色与数据库引擎（`db_engine_label`）。
- **.workspace > .topbar 顶栏**：按 active_page 用 if/elif 输出页面大标题；
  右侧固定放「产线状态药丸（id=topbarLineStatus）、1/2/5/10x 倍速按钮（onclick=setSimSpeed）、
  音效开关（toggleAudioMute）、大屏模式（toggleFullscreen）、时钟 id=clock、用户名+角色 chip、
  **修改密码链接（`/change_password`，class=btn-change-pwd，样式在 base.css）**、退出链接」。
- **main.page-content**：先用 `{% set page_meta = {...} %}` 定义每页的英文眉题/中文标题/说明三元组，
  命中 active_page 就渲染 `.page-heading` 页头；然后是 `{% block content %}` 页面主体。
- 页面外还固定挂了三个全局浮层：确认弹窗 `#confirmMask`、工位诊断抽屉 `#stationDrawerMask`、
  Toast 容器 `#toastContainer`——所有页面共用 app.js 里的弹窗/抽屉/提示逻辑。

### 1.2 底部脚本加载顺序（决定 JS 全局变量从哪来）

```html
<script src="js/form.js"></script>
<script>window.API_BASE = '{{ api_base }}';</script>   <!-- 8080 地址，来自 context_processor -->
<script src="js/app.js"></script>
<script src="js/base.js"></script>                     <!-- updateTopbarStatus() 每 3 秒轮询 /api/stats -->
{% block extra_js %}{% endblock %}                      <!-- 各页专属 JS 最后加载 -->
```

CSS/JS 链接上带的 `?v=20260918a` 是手工版本号，配合 `SEND_FILE_MAX_AGE_DEFAULT=0` 做缓存刷新。

## 2. home.html —— 数据采集与看板首页（路由 GET /）

- 继承母版，`extra_css` 引入 `css/home.css`（由原 monitor.css 更名，只此一页使用；
  页内 OEE 卡紫色描边、自适应 KPI 网格、演示按钮等局部样式也已收进 home.css）。
- `extra_js` 引入 `js/home.js`（从 static 根目录迁入 js/）。
- 首屏数据注入：
  ```html
  <script type="application/json" id="initialLine">{{ line|tojson }}</script>
  ```
  把 server.py 传来的产线快照以 JSON 文本形式藏在页面里，home.js 启动时先渲染它，
  不等第一次网络请求，避免开屏空白。
- 页面主体是大屏看板：顶部 4~5 张 KPI 卡（工单总数、计划量、完成量、一次合格率、OEE 等），
  `.station-deck` 七列工位状态卡，`.monitor-main` 双栏（产线遥测 + 事件流）。
- 绝大多数 DOM 都是「空骨架 + 带 id」，真正内容由 home.js 每 2 秒轮询 8080 后填充；
  空骨架的 class/id 命名与 home.js 的渲染函数一一对应（renderStats/renderLine/renderEvents）。

## 3. line.html —— 在制追踪 / 虚拟仿真（路由 /line 与 /virtual 共用一个模板）

这是「一套模板两种模式」的关键设计：

```html
<script>window.LINE_MODE = '{{ mode }}';</script>   <!-- real 或 virtual -->
```

server.py 渲染时传入 mode，line.js 据此决定调 `/api/line`（真实）还是 `/api/virtual`（虚拟），
以及是否额外拉 `/api/logs?category=line`。

页面结构：

- 顶部操作条：开始/停止/复位/急停按钮（管理员操作，真实模式写 PLC，虚拟模式只动内存），
  虚拟模式还有故障注入/清除按钮；
- 4 个选项卡（`.tab` + data-tab）：
  1. `flow` 工艺流程：process-rail 工序轨 + 7 工位纯 CSS 机台图（由 app.js 的
     renderProcessRail/renderFactoryLine 生成）；
  2. `plc` 寄存器：HR0/1/2/4/5/6 当前值表格；
  3. `robot` 机械臂：位置坐标、动作状态；
  4. `trace` 追溯：过站记录表（循环 records，列=工单/工位/结果/时间）。
- 底部日志流 `.log-list`：真实模式来自数据库日志，虚拟模式来自 VIRTUAL_LOGS 内存日志。

## 4. orders.html —— 作业指示与工单排产（路由 GET/POST /orders）

### 4.1 新建工单表单（传统 POST，提交到 6021 本页）

`<form method="post" action="/orders">` 内字段的 name 必须与 server.py 的
`request.form[...]` 一一对应：

| 表单字段 name | 控件 | 后端用途 |
|---|---|---|
| order_no | 文本（默认值 default_order_no，即 WC日期-序号） | 工单号，留空自动生成 |
| product_code | select 下拉（{% for p in products %}） | 关联产品；选规格时由 orders.js 联动 |
| quantity | number | 计划数量（≤0 不落库） |
| priority | select 1/2/3 | 优先级（色条样式在 app.css） |
| due_date | date | 交期 |
| remark | textarea | 备注 |

还有「填入示例」按钮调 orders.js 的 fillSampleOrder()。

### 4.2 工具栏与工单表

- 工具栏：状态筛选按钮组（全部/待生产/生产中/已完成，由 orders.js 切换 display）、
  关键字搜索框（按单号/产品/备注模糊过滤）。
- 工单表用 `{% for order in orders %}` 渲染：优先级色条、单号、产品、计划/完成数、
  交期、进度控件、状态徽标、操作链接。
- 进度控件和状态徽标不直接写 HTML，而是 import 宏：
  ```jinja
  {% import "_widgets.html" as w %}
  {{ w.order_progress_ctl(order) }}
  {{ w.order_status_ctl(order) }}
  ```
  宏渲染出的 `.progress-ctl` / `.status-ctl` 由 progress.js 接管全部交互（拖拽改进度、切状态）。
- 操作列的老链接 `/update_status/<id>/<状态>`、`/delete_order/<id>` 带 `data-confirm`
  由 app.js 全局代理弹确认框；下发「生产中」按钮用 `{% if is_admin %}` 只对管理员显示。

## 9. users.html —— 用户权限管理（仅管理员）

- 用户表 `{% for u in users %}`：账号、姓名、角色徽标、状态、学号、操作按钮组。
- 每行是一个 `<form method="post" action="/users">`，隐藏字段 action + user_id，

## 13. login.html / register.html / forgot_password.html —— 三个独立整页

三者**不继承 base.html**（未登录时没有侧栏顶栏），都引 app.css + console.css，
再加各自的同名专属 CSS（`css/login.css`、`css/register.css`、`css/forgot_password.css`，
深色渐变、发光边框、玻璃卡片、网格/扫描线动效，动画名各带页面前缀避免冲突），
以及同名专属 JS（`js/login.js`、`js/register.js`、`js/forgot_password.js`）：

- 一个 `<canvas id="particles-bg">` 铺满背景，requestAnimationFrame 画漂浮粒子与连线，
  纯视觉动效；三份粒子代码结构几乎相同，是有意的（三个页面互不依赖、各自可独立打开）。
- login.js / forgot_password.js 额外绑定验证码图片点击刷新；公共 js/form.js 负责
  required 空值提示。

### login.html

`<form method="post" action="/login" id="loginForm">`：username、password、captcha（验证码）
三个输入，验证码图片 `<img id="captcha-img" src="/captcha">` 由 login.js 绑定点击刷新；
错误提示由 server.py 渲染到 `.error-msg`。

### register.html

POST /register，字段 name：username、display_name、student_id、password、confirm；
前端 required + 简单约束，后端还有完整正则与唯一性校验（见 11 号讲解）。

### forgot_password.html

POST /forgot_password，字段：username、student_id、new_password、confirm、captcha；
按「账号 + 学号」重置密码，内置 admin 被后端拒绝。

## 13a. change_password.html —— 修改密码（登录用户自助页，路由 GET/POST /change_password）

独立整页（与登录页同款科技面板风），配套 `css/change_password.css` 与
`js/change_password.js`（粒子背景 + 新密码长度/两次一致的前端预校验 + 提交防连点）。

- 入口：base.html 顶栏用户区的「修改密码」链接，所有登录用户可见，**只能改自己的密码**
  （账号取 session，不信任表单）。
- 表单 id=changePasswordForm，字段 name：`old_password`、`new_password`、`confirm`；
  POST 到本页。
- 后端校验顺序：旧密码必须正确 → 新密码至少 6 位 → 两次输入一致 → 新密码不得与旧密码相同；
  成功后更新 password_hash、清用户缓存、写日志，并**立即重新 sign_in 刷新会话指纹**
  （session_signature 含密码哈希，不刷新会被下一次请求判失效踢下线），最后 303 带
  `?message=` 回本页显示成功提示。

## 16. _widgets.html —— Jinja 宏库（不是页面）

定义 3 个可复用宏，被 orders.html、production.html import：

### 16.1 order_progress_ctl(order)

渲染工单进度交互控件 `.progress-ctl`，并把后端数据写进 data-* 属性交给 progress.js：

- data-id（工单 id）、data-qty（计划量）、data-done（完成数）、data-progress（百分比）、
  data-status（状态）；
- 内部结构：−/+ 步进按钮（.progress-step，带 data-delta，边界值自动 disabled）、
  可聚焦可拖拽的 .progress-track（role=slider，含 fill 填充条与 thumb 滑块）、
  数字输入框 .progress-input（min=0 max=计划量）、
  `.progress-stations` 7 个小点（按百分比点亮，表示所处工位）。
- 百分比 pct 的 Jinja 计算：已完成强制 100%；否则用库里的 progress；都没有则 完成数×100÷计划量。

### 16.2 status_badge_class(st)

把状态文字映射成徽标 class：待生产→badge-wait、生产中→badge-run、暂停→badge-pause、
返工→badge-rework、其他（已完成）→badge-done。与 progress.js 里的 STATUS_BADGE 映射保持一致。

### 16.3 order_status_ctl(order)

渲染 `.status-ctl`：一个 `.status-btn` 徽标按钮 + 隐藏的 `.status-menu` 五个状态选项
（待生产/生产中/暂停/返工/已完成），点击展开由 progress.js 的事件委托处理，
选中后 POST /api/orders/<id>/progress 改状态。

## 17. HTML 与后端表单/接口的衔接小结

- **服务端渲染数据**：循环/表格/默认值全部来自 server.py 视图传入的变量
  （orders、stats、logs、station_defs、products、line 等），权限入口靠 {% if is_admin %}。
