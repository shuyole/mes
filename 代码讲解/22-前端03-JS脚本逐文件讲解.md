# 22 · 前端代码讲解（三）：JS 脚本逐文件讲解（static/js/ 共 19 个）

> 目录：`frontend/static/js/`，19 个原生 JavaScript 文件（无框架、无打包工具）。
> 模块化约定：每个页面都有同名 JS（login.js、orders.js……），母版本身对应 base.js。
> 加载关系：base.html 全局加载 **js/form.js → js/app.js → js/base.js**（每页都有）；
> 登录/注册/找回/改密四个独立页加载 form.js + 各自同名 JS；
> 各业务页再通过 extra_js 加载自己的专属脚本。
> 所有调接口的代码都写 `fetch('/api/...')`，由 app.js 劫持 fetch 后自动补上
> `window.API_BASE`（8080 地址）并带上 Cookie。
>
> 文件全清单：form.js、app.js、base.js（公共三件）、home.js、line.js、orders.js、
> production.js、progress.js、hmi.js、station_st01.js、settings.js、users.js、recipes.js、
> alarms.js、forbidden.js（母版体系 11 页）、login.js、register.js、forgot_password.js、
> change_password.js（独立整页 4 个）。

## 1. form.js（约 20 行）—— 表单校验提示增强

被所有页面加载，但只对表单起作用：

- 页面加载后给所有 `[required]` 控件绑定 `invalid` 与 `input` 事件；
- 原生提示文案不好看，改用控件上的 `data-hint` 属性文案（如「请输入账号」）
  通过 `setCustomValidity` 显示；用户开始重新输入（input 事件）立刻清空自定义错误，
  避免错误提示残留。
- 纯增强，不阻止后端二次校验（登录/注册/找回密码/建单的服务端校验仍是真正的安全边界）。

## 2. app.js（约 519 行）—— 全局基础库（最重要的 JS 文件）

母版加载后全页面生效，提供「跨端口请求、心跳、音效、弹窗、抽屉、快捷键、公共渲染」。

### 2.1 时钟

启动即更新 `#clock` 并每秒刷新为 HH:MM:SS，对应顶栏时钟。

### 2.2 fetch 劫持：统一对接 8080

保存原生 `window.fetch` 后重写：

- 若 URL 以 `/api/` 开头，自动拼成 `window.API_BASE + url`（解决 6021 页面直连 8080 的跨端口）；
- 所有请求默认加 `credentials: 'include'`（带 session Cookie），
  非 GET 且未手动指定时默认 `Content-Type: application/json`，对象 body 自动 JSON.stringify；
- 响应为 **401（未登录/会话失效）时统一跳 6021 的 /login**，业务代码不用各自处理；
- 其他响应原样返回给调用方。

### 2.3 心跳与通用请求

- 每 5 秒 GET `/api/ping` 探活：会话过期会被上面的 401 拦截跳登录；
- `getJSON(url)`：GET 并解析 JSON 的小封装（首页另有带 AbortController 的版本）；
- `postJSON(url, data)`：POST JSON，成功按返回 message 弹成功 toast，失败弹错误 toast，
  网络异常兜底提示「后端服务不可达」。alarms.js 等页面脚本直接复用它。

### 2.4 Web Audio 工业音效

用浏览器 AudioContext 现场合成（无音频文件）：

- 按键 click（短促高频）、操作成功 success（三和弦上行）、报警 alarm（双音交替）；
- 首次用户交互后才 resume 音频上下文（浏览器自动播放策略要求）；
- 静音状态写 localStorage，`toggleAudioMute()` 切换并更新顶栏按钮 active 态，快捷键 M。

### 2.5 反馈与确认

- `showToast(msg, type)`：在 `#toastContainer` 动态建 toast，3 秒后移除，成功/错误/普通三色；
- `showConfirm(text)`：返回 Promise，用母版里的 `#confirmMask` 自定义确认框
  （确定 resolve(true)、取消/遮罩/关闭 resolve(false)）；
- 全局事件代理：点击任何带 `data-confirm` 的元素（链接或按钮）时先弹确认框，
  取消则阻止默认行为——orders/users 页的删除、状态流转都靠它。

### 2.6 倍速、全屏、快捷键

- `setSimSpeed(speed)`：POST `/api/simulation/speed`，成功后切换 1/2/5/10x 按钮 active 态；
- `toggleFullscreen()`：切换 `document.documentElement` 全屏 + 给 body 加/移
  `scada-fullscreen` 类触发大屏 CSS，快捷键 **F**；
- 全局 keydown：M 静音、F 全屏、Esc 关诊断抽屉。

### 2.7 工位诊断抽屉

- `openStationDrawer(code)`：GET `/api/line/station/<code>/diagnose`，
  把传感器点表（ON/OFF 灯）、工艺参数（实测/标准/公差）、质量标准、实时状态与过站量
  渲染进 `#drawerStationBody`，并挂「动作自检」（POST .../test）和「注入故障」按钮
  （后者仅管理员，根据页面上是否存在相关标记控制）；
- `closeStationDrawer()`：加隐藏类。任何页面点击工位卡（全局代理 `.station-card`/
  带 data-station 的元素）都能打开抽屉。

### 2.8 演示数据与公共渲染

- `seedDemoOrders()`：先 showConfirm 再 POST `/api/demo/seed_orders`，成功刷新页面；
- 工位与产线的公共渲染函数（line 页、首页、HMI 复用）：
  - `stationClass(status)`：工位状态 → CSS 类（idle/run/done/fault/offline）；
  - `renderProcessRail(stations)`：渲染工序轨节点完成态；
  - `renderFactoryLine(stations, ...)`：渲染 `.machine.v1~v7` 七工位机台图与机械臂位置。

## 3. home.js（约 175 行）—— 首页大屏看板

严格模式 IIFE，所有逻辑封在内部避免污染全局。

- **首屏**：读取 `#initialLine` 里的 JSON 立即渲染一次（无网络等待）。
- 渲染函数：
  - `renderStats(stats)`：KPI 数字，其中 **OEE = 0.96 × 0.94 × 良率**（时间开动率×性能开动率×合格率）；
  - `renderLine(line)`：状态药丸、七工位 deck、当前工单进度；
  - `renderDetail/plc`：产线遥测（产量、合格、不良、节拍、当前工位）；
  - `renderEquipment()`/`renderEvents(logs)`：机械臂/设备摘要与事件流列表。
- **数据获取策略**：
  - 自写带 `AbortController` 的 getJSON（8 秒超时），防止慢请求堆积；
  - `refresh()` 用 `Promise.all` 并发取 `/api/stats` 与 `/api/plc_status`，
    `/api/logs` 做 10 秒节流（日志不必 2 秒拉一次）；
  - `busy` 标志防重入；`document.hidden` 时跳过本拍（标签页不可见不浪费请求），
    监听 `visibilitychange` 回到页面立即强制刷新；
  - setInterval 每 2 秒一次；任何同步异常都进 notice 提示而不中断定时器。

## 4. line.js（约 107 行）—— 在制追踪 / 虚拟产线（line.html 专属）

- 读取 `window.LINE_MODE`（real/virtual）决定数据地址：
  真实模式请求 `/api/line` + `/api/logs?category=line`；虚拟模式请求 `/api/virtual`
  （响应已自带 logs/records，不再请求日志接口）。
- 选项卡：点击 `.tab` 切换 4 个 `.tab-panel`（flow/plc/robot/trace）的显示。
- 控制动作：
  - `sendCommand(cmd)`：管理员按钮 → POST `/api/line/command`，
    带 source（virtual 模式=virtual）与需要时的 order_id；
  - `injectFaultST()` / `clearFaultST()`：注入/清除故障；
  - 每次操作后立即 refresh()。
- `refreshLine(data)`：更新概要卡（工单/产品/数量/进度/节拍）、机械臂坐标与动作、
  调 app.js 的 renderProcessRail/renderFactoryLine 渲染流程与机台、
  更新 HR 寄存器表、日志流、追溯记录表。
- 定时器每 1.5 秒轮询一次。

## 7. progress.js（约 315 行）—— 工单进度控件（orders/production 两页复用）

接管 `_widgets.html` 宏渲染出的 `.progress-ctl` 与 `.status-ctl`，是交互最复杂的脚本。

### 7.1 状态与绘制

- `STATUS_BADGE`：状态文字 → 徽标 class（与宏 status_badge_class 保持一致）；
- `inferStatus(pct, done, qty)`：根据百分比/数量推断当前应显示的状态；
- `paintBar(ctl)`：设置 fill 宽度、thumb 位置、7 工位点亮点、百分比文本、数字框值、±按钮禁用；
- `paintStatus(ctl)`：更新状态徽标文字与颜色；
- `paintActions`：根据状态/权限调整操作区。

### 7.2 保存（带防乱序序号）

- 每个控件维护 `_seq` 序号；`saveProgress(ctl, payload)` 每次 +1 并把序号带进闭包，
  POST `/api/orders/<id>/progress`；响应回来时只在「仍是最新一次请求」时才回填，
  避免快速连续操作时旧响应覆盖新结果；
- 成功后用服务端返回的最新视图（completed_qty/progress/status/current_station）重绘，
  失败弹 hudToast 并回滚到保存前状态。
- 自带轻量 `hudToast()`（控件局部小提示），不依赖 app.js 的 toast 也能工作。

### 7.3 事件委托（整页只绑少量监听器）

在 document/容器上委托处理：

- `.js-finish` / `.js-rework`：一键完工 / 返工；
- `.progress-step`：±按钮按 data-delta 增减件数；
- 数字输入框 change：直接保存绝对完成数；
- `.status-btn` / `.status-menu button`：展开状态菜单、选择 5 种状态并保存；
- 点击菜单外区域自动收起。

### 7.4 Pointer Events 拖拽 + 键盘可达性

- 拖拽：`pointerdown` 在 thumb/轨道上 → `setPointerCapture` 捕获指针，
  pointermove 用 `requestAnimationFrame` 节流，`qtyFromPointer` 按点击位置占轨道宽度的比例
  换算件数（0~计划量），pointerup 保存；
- 键盘：轨道 `role="slider" tabindex="0"`，支持 ←/↓ 减一件、→/↑ 加一件、
  Home 归零、End 满量，满足键盘操作与读屏可达性；
- 初始化：对页面上所有 `.progress-ctl` 执行一次 paintBar/paintStatus，
  与服务端渲染保持一致。

## 8. hmi.js（约 221 行）—— HMI 上位机控制台

- `refresh()`：GET `/api/plc_status`（1.5 秒一次），刷新：
  - 连接信息（IP/端口、连接点颜色、累计读/写次数、最后读写时间、错误信息）；
  - 三色安灯 `renderLeds()`：HR0=1 绿灯、=3 红灯（报警音）、暂停黄灯、停止全灭，
    未连接全部灰暗；
  - 当前工单卡（单号/产品/进度）；
  - 机械臂状态（位置、运行/故障）；
  - HR0/1/2/4/5/6 寄存器显示；
- 控制：
  - `sendCommand(cmd)`：POST `/api/line/command`，按结果播放 success/alarm 音效并立即刷新；
  - `writeRegister()`：手动写保持寄存器 → POST `/api/plc/write`（输入地址与值，做数字校验）；
  - PLC 地址编辑：`bindPlcAddrEditor()` 让 IP/端口文本框可就地修改，
    `markPlcAddrDirty()` 标脏（显示「未保存」），回车或失焦调 savePlcAddr()
    → POST `/api/plc/config`（reconnect=true），成功后提示重连中；非管理员不允许编辑。

## 11. 模板中保留的内联脚本（不属于任何 JS 文件）

模块化后模板里只剩「数据/配置注入」类一行脚本，它们无法也不应抽成静态文件：

- base.html：`<script>window.API_BASE = '{{ api_base }}';</script>`（8080 地址，服务端注入）；
- line.html：`<script>window.LINE_MODE = "{{ mode }}";</script>`（real/virtual）；
- home.html / production.html：`#initialLine`、`#productionData`
 （type="application/json"），是「服务端数据 → JS」的桥；
- 部分按钮保留 `onclick="sendCommand(...)"` 等写法，调用的是上述 JS 文件暴露的全局函数。
